# 3D 기준면 위에 2D 잔차를 더하는 얼굴 회전

먼저 두상과 안구를 입체로 회전시킨다. 그 결과가 원화의 얼굴 인상을 깨뜨리는 부분에만 부위별 변형을 더한다. 외부 모델에서 추출한 정점이나 보정 계수를 이 캐릭터에 이식하지 않는다. 비교 실측은 [측정 결과](measurements.md), 형상 후보 비교는 [표면 비교](surface-comparison.md)에 있다.

## 1. 좌표와 3D 기준

화면 오른쪽을 x, 아래를 y, 관객 쪽을 z 양수로 둔다. 정면 원화의 점 p와 두상 중심 c, 반지름 r에 대해 로컬 좌표는 다음과 같다.

```text
x = p.x - c.x, y = p.y - c.y
z = sign × sqrt(max(0, r² - x² - y²))
q = Rz(roll) Rx(pitch) Ry(yaw) [x,y,z]
B(p,a,b,c) = headCenter + q.xy
```

앞쪽은 sign=+1, 뒤쪽은 -1이다. 구 밖의 점은 원화의 x,y를 보존하고 z=0에 둔다. 이는 구의 같은 x에 있는 위, 아래 가장자리에서 세로 띠를 늘인 기준이다. |x|>r이면 가장 가까운 가장자리에서 가로 연장도 포함된다. 띠 전체가 3D에서 함께 회전한다. 회전 뒤 화면 y에 원래 길이를 덧붙이는 구현과 다르다. 이 형상은 머리카락의 실제 곡면을 복원한 것이 아니며, 길게 늘어진 뒷머리의 pitch에는 큰 오차가 남을 수 있다.

투영은 직교투영이다. 화면 원근을 추가하려면 카메라 거리와 회전 중심의 깊이를 별도로 정해야 한다. 이번 자료로 그 값들을 유일하게 결정할 수 없다. 파라미터 값 30도 물리적인 30°를 뜻하지 않는다. 파라미터→실제 각도 보정과 표면 보정을 구분한다.

안구는 머리에 연결된 자식 구다. 눈 중심 e와 안구 표면 v에 대해 `world = Rhead(e + Rgaze v)`이다. 눈 중심에 머리 회전을 적용한 뒤 눈 표면에 머리 회전을 다시 적용하면 이중 회전이다. 눈꺼풀 개구부의 마스크는 별도로 유지한다. 얼굴 회전에서 눈꺼풀을 눌러도 안구의 시선 회전까지 같은 비율로 누르면 안 된다.

## 2. 보정은 최종 좌표와 기준 좌표의 차이

서소영 원화에서 직접 만든 정면, 좌우, 상하, 네 대각선 목표 점을 Aij라고 하자. 정면 포함 3×3 파라미터 격자에서 다음만 저장한다.

```text
Dij(p) = Aij(p) - B(p, yaw_i, pitch_j, 0)
P(p,u,v) = B(p,u,v,0) + bilinear(D,u,v)
Final = center + Rz(roll) (P - center)
```

보정은 roll 이전의 XY 공간에서 적용한다. 전체 XY 변형을 잔차로 잘못 저장하면 기본 구면 이동이 두 번 더해진다. 정면을 보존하려면 목표 가운데 키폼을 정면 원화와 같게 작성한다. `bakeResidual`은 임의의 가운데 키폼도 허용하므로 이 조건은 작성자가 지켜야 한다.

대각선 상호작용은 `Jxy = Axy - Ax0 - A0y + A00`으로 분리한다. 그러나 J가 전부 일러스트 보정은 아니다. 순수 3D 회전도 yaw와 pitch의 결합항을 만든다. 실제로 더할 상호작용은 `Jactual - J3D`다. 축에서 0, 코너에서 지정값이 되는 `max(0,sx*u) max(0,sy*v)`의 네 기저로도 표현할 수 있다. 3×3 잔차의 조각별 쌍선형 보간이 이 역할을 포함한다. 축에서 기울기가 꺾일 수 있으므로 필요할 때만 원화 키폼을 추가하며, 근거 없이 평활화해 원래 코너를 바꾸지 않는다.

## 3. 부위별 소유권

| 부위 | 3D 기준에서 확인할 문제 | 보정 소유자 |
| :--- | :--- | :--- |
| 볼, 턱 윤곽 | 구의 외곽은 depth 기울기가 커 좁게 눌리거나 턱 끝이 말려 들어간다 | 얼굴 외곽 격자에서 폭, 턱 곡선을 따로 보존한다 |
| 눈, 눈꺼풀 | 같은 구 위의 점만으로는 양쪽 눈의 서로 다른 압축을 표현하기 어렵다 | 좌우 눈의 국소 격자에 각각 압축, 시어를 둔다 |
| 안구 | 눈의 구면 시차와 안면의 압축을 분리해야 한다 | 자식 구의 시선 + 눈 개구부, 눈꺼풀 격자 |
| 코, 입 | 피부보다 큰 이동과 다른 세로 압축이 필요하다 | 국소 깊이와 독립 잔차; 입 모양 축과 얼굴 회전 축을 분리 |
| 귀 | 얼굴 중심과 같은 이동량이면 머리에 붙은 위치가 어긋난다 | 측면 부착 위치와 귀 격자 |
| 앞머리, 정수리 | 구 밖 띠의 깊이가 0으로 떨어지며 정수리 볼륨이 평평해진다 | 머리카락 외피 깊이와 상단 격자; 앞머리 흔들림은 자식으로 유지 |
| 옆, 뒷머리 | 가려진 쪽이 드러날 때 기하만 움직여도 빈 곳은 채워지지 않는다 | 뒤쪽 외피, 여분 원화, 겹침 영역, 가림 순서; 잔차만으로 새 픽셀 생성 불가 |
| 목 | 머리와 함께 강체 회전하면 어깨 연결부가 움직인다 | 아래는 몸에 고정하고 위만 턱 부착점 변위에 따라 움직이는 띠 |

목은 `Pneck = Prest + w(p) (jawMoved-jawRest)`를 최소 기준으로 쓴다. w=0은 어깨, w=1은 턱이다. 호흡과 좌우 스웨이는 머리와 y576 위쪽 목에 같은 이동량을 더하고, 목 아래와 몸은 상단 가중치로 자연스럽게 감쇠한다. 필요하면 그 위에 목 자체의 국소 잔차를 둔다. 피부를 뒤집거나 턱에 가려질 영역을 새로 그리는 작업은 이 수식의 기능이 아니다.

## 4. 실행 모듈과 사용 경계

[src/head-turn.mjs](../src/head-turn.mjs)는 입체 회전, 앞, 뒤 구면/띠, 자식 안구, 3×3 잔차, 목 부착을 제공한다. [예제](../examples/seosoyoung-head.mjs)는 서소영 원화 좌표의 초기 중심, 반지름, 눈 위치를 연결한다. 이 좌표는 출발점이며 최적화한 최종 서소영 리그가 아니다.

잔차는 정점마다 한 개를 만들 수 있다. 격자 제어점에서 잔차를 작성하는 경우 실제 메쉬 위치로 공간 보간하는 부분은 사용하는 렌더러가 담당한다. 이 모듈은 Cubism의 quad warp, blend shape constraint, glue, 마스크, 그리기 순서나 물리 엔진의 대체 구현이 아니다. 얼굴 애니메이션 뷰어에는 아직 연결하지 않았다.

외부 모델의 잔차를 각 모델의 비공개 측정 환경에서 계산해 9개 기준 포즈와 그 사이 16개 포즈에 대조했다. 기준 키폼에서 일치하는 것은 구성상 당연하다. 중간 포즈의 별도 오차와 긴 머리의 남은 오차를 함께 보고한다. 서소영에 적용할 잔차는 서소영의 목표 키폼으로 새로 작성해야 한다.

## 서소영 뷰어의 9방향 보정

`bundle/face-outline.mjs`와 `bundle/face-features.mjs`는 서소영의 별도 실측 데이터를 사용한다. yaw는 -45/0/+45, pitch는 -30/0/+30이며 양의 pitch는 위를 보는 방향이다. `pose-grid.mjs`의 삼각함수 cardinal 기저는 아홉 키폼에서 정확하고 가운데 축에서도 기울기가 이어진다. 정면 원화 좌표를 보존하고, r11을 포함한 좌우 타깃의 정면 대비 변위를 거울 평균한다. 구면 투영도 각 행의 대칭 반폭에서 계산하므로 정면의 작은 비대칭이 회전 변위에 섞이지 않는다. 원시 측정은 보정 데이터와 따로 보존한다.

여섯 상하 레퍼런스의 카메라 이동은 먼저 제거한다. `reference_registration.mjs`가 r11 자식 안구의 3D 피벗을 해당 자세로 회전하고, 레퍼런스의 양안 중점을 그 중점에 평행 이동한다. 원시 측정과 등록 이동량은 `source/viewer/face-feature-fit.json`에 함께 남긴다. 눈의 형태, 시선, 깜빡임과 눈썹 및 입 모양은 등록된 중심 주변에서 적용하며 마지막에 고개 기울임을 적용한다.

얼굴 윤곽은 원본 광대 y465부터 턱 y616까지의 마스크 실측을 쓴다. `fit_depth.py`는 정면 원화를 1024 정사각 캔버스에 `(152,20)`으로 맞춰 Depth Anything V2 Small의 상대 깊이를 추정하고, ±45° 윤곽에서 복원한 `z_edge(y)`에 선형 피팅한다. 좌우 대칭화와 sigma 4px 평활화를 거친 격자는 내부가 외곽보다 앞으로 나오며, y616 턱 중심은 외곽 깊이로 부드럽게 이어진다. 결과는 `source/viewer/face-depth.json`과 `bundle/face-depth.mjs`에 저장한다.

`faceLift`가 이 깊이 격자를 이용해 마스크 하관을 실제 3D 회전시키고, `outlinePitchShift`는 회전 뒤의 상대 높이 `s_rot`에서 2D 레퍼런스 폭과 중심을 다시 맞춘다. 상향에서는 광대 위쪽 폭 보정을 0 이하로 제한하고, 하향에서는 레퍼런스보다 10px 넘게 더 좁아지지 않게 한다. `fit_outline.py`의 pitch 샘플도 윤곽 외곽 깊이를 적용한 3D 회전 스팬에서 추출한다. SAM 3가 목까지 선택한 원본 마스크도 보존하고, 측정한 턱선으로 목을 제외한다. 목 상단은 턱의 세로 이동량을 따른다.

여섯 앞쪽 머리카락 파츠의 위치는 `canopyWorld([x,y], p)` 하나가 소유한다. 동일한 원화 좌표와 포즈는 같은 XYZ를 반환한다. 상단은 중심에서 외곽으로 깊이가 단조 감소하는 `hairLift`를 사용하고 구레나룻 하단만 실측 가닥으로 이어진다. 파츠별 깊이 오프셋을 제거했고 두피 y245 위의 흔들림은 0이다. `pipeline/canopy_mesh.py`는 겹치는 텍스처가 같은 캔버스 격자와 삼각형 대각선을 쓰게 하여 GPU의 내부 보간 차이도 줄인다. 레이어 순서는 옆머리, 정수리, 앞머리, 머리핀이다. 측면 레퍼런스 RGB 스탬핑은 모든 파츠에서 0이고, 옆머리는 피부 깊이를 검사한다. 기존 뒤머리 바탕의 상단은 뒤반구에 놓아 아래를 볼 때 드러나는 정수리를 채운다.

`hair_albedo.py`는 외곽의 저주파 림라이트를 내부 암갈색 Lab 톤으로 낮추면서 고주파 머릿결을 남긴다. 눈썹 마스크와 겹치는 앞머리 픽셀은 위아래 관통 가닥만 유지한다. `prepare_front_hair.py`는 고정 입력에서 다시 시작하며, 정수리의 새 메움은 y230~250에서 사라진다. 측후두부 텍스처는 밝은 테두리를 샘플에서 제외한 뒤 정면 내부 톤의 평균과 대비에 맞춘다.

재생성은 필요할 때 `pipeline/fit_depth.py`를 먼저 실행하고 `pipeline/stage3_build_viewer.py`로 뷰어 산출물을 만든다. 깊이 추정 도구는 별도 `requirements-depth.txt`의 CPU PyTorch와 Transformers를 쓰며, 모델 가중치는 생성 때만 필요하다. 캐시된 마스크와 고정된 모델 revision은 재생성 입력으로 남긴다. 기본 Python 의존성은 `requirements.txt`에 있으며 빌드 환경은 워크트리 전용으로 준비한다. 검증은 `pipeline/test_outline.mjs`, `test_hair_shell.mjs`, `test_stereo.mjs`, `test_attachment.mjs`, `test_corrections.mjs`, `test_sphere_3d.mjs`와 `verify_viewer.py`로 실행한다. `verify_viewer.py --poses-only`는 DPR 2의 아홉 자세 및 좌우 45도 캡처와 귀, 구슬, 이마 검사를 수행한다.

## 근거와 해석

Live2D 공식 절차도 부위별 XY 디포머를 구성하고, 네 대각선 키폼을 생성한 뒤 어색한 부분을 수정하도록 안내한다. 이는 측정에서 확인한 부위별 격자와 대각선 전용 변형을 해석하는 참고다. [공식 XY 튜토리얼](https://docs.live2d.com/en/cubism-editor-tutorials/xy/), [네 코너 생성](https://docs.live2d.com/en/cubism-editor-manual/synthesize-corners/).

공식 3D 회전 표현 기능은 깊이, 회전 중심, 실제 각도 범위와 원근을 별도로 설정한다. 이번 일반 모듈의 방향과 부합하지만, 공식 기능의 내부 알고리즘을 복제하거나 두 시험 모델이 그 기능으로 만들어졌다고 주장하지 않는다. [공식 3D 회전 표현](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression/).
